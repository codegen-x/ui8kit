# ui8kit (codegen-x/ui8kit, branch `ui8kit3`)

One source of truth for UI that has to exist in more than one runtime. The sources are **specs, schemas, fixtures and content**.
The primitives come from **UI8Kit 3** (installed by the `ui8kit` CLI into `packages/kit/<runtime>`). Everything above them (the
compositions, the organisms and blocks, the screens, the shared app core and the host apps) is **generated** by `packages/compose-gen`
onto `packages/kit-compose` for eight runtimes: Svelte 5, React 19, Vue 3 and Solid (each with a host app), and the server template
engines Go templ, Twig, Jinja2 and Latte (held to DOM parity with React by the kit-compose tests with the real engines).

New here? Read **[docs/specs-guide.md](docs/specs-guide.md)**: how to author specs, run the gates and add an organism end to end.

```
packages/kit/<rt>          UI8Kit 3 primitives (19 + slot, utils) per runtime, installed by `bunx ui8kit@3 add`, never edited by hand
packages/compose-gen       the generator: specs, schemas, fixtures, content, the authoring builder, the emitters, `compose-gen check` and `e2e`
packages/kit-compose       the generated compositions, organisms and blocks per runtime (@codegen-x/<rt>-compose) and the build scripts (src/)
packages/shared/app        @ui8kit/app-shared: dictionary, data, menus, runtime core of the host apps (generated, emitted once)
packages/skins             the skins (themes) and their build;  packages/ui-gates: portable source/HTML gates
packages/tooling           audit, zones, kit-check, ui8px and the rules gate (packages/tooling/rules)
packages/{taste-screens,taste-data,panorama}   hand-written Svelte screens, their data and the Three.js panorama (Discovery, Magazine)
apps/host-{svelte,react,vue,solid}   one host per TS runtime, renders any screen by name at /<screen>/#/<route> (hand-written: xgen.app.json only)
apps/{magazine,discovery}  hand-written Svelte apps on @codegen-x/svelte-compose
```

## The rule

> **Nobody edits generated files by hand**: `packages/kit-compose/<runtime>`, `apps/host-*/gen`, `packages/shared/app` (header
> `Code generated by ... DO NOT EDIT.`) and `packages/kit/**` (installed by `ui8kit`).
> What people write: specs, schemas, fixtures and content (`packages/compose-gen/{specs,schema,fixtures,content}`), the builder of
> organisms and screens (`packages/compose-gen/screens/src/authoring`), the composition map and recipes (`packages/kit-compose/src/map.ts`,
> `packages/kit-compose/variants`), skins (`packages/skins`) and one `xgen.app.json` per host app.
> A landing, a theme or the block gallery is a **screen spec** (`packages/compose-gen/specs/screens/*.json`), not an app: adding a screen adds no app directory.
> `bun run check` (`compose:check`) regenerates everything in memory and **fails on any difference** from the disk.

## Clone

```
git clone <url> && cd ui8kit && bun install
bun run hooks:install                 # once per clone: pre-push runs check + audit
```

No submodules and no symlinks any more (the `vendor/codegen` submodule went with xgen).

## UI8Kit 3

Primitives come from the public UI8Kit 3 toolchain, installed by the CLI, never copied by hand:

- generator and API docs of the primitives: [ui8kit/codegen](https://github.com/ui8kit/codegen) (`docs/primitives`, `docs/runtimes`)
- registry: [@ui8kit/registry](https://www.npmjs.com/package/@ui8kit/registry) 3.2.0 ([ui8kit/registry](https://github.com/ui8kit/registry))
- CLI: [ui8kit](https://www.npmjs.com/package/ui8kit) 3.2.1 ([ui8kit/cli](https://github.com/ui8kit/cli)), a root devDependency
- data contract: [@ui8kit/contract](https://www.npmjs.com/package/@ui8kit/contract) 0.2.0 ([ui8kit/contract](https://github.com/ui8kit/contract)), used by `codex:validate`

`packages/kit/<runtime>` (svelte, react, vue, solid, templ, twig, latte, jinja2) holds the 19 primitives + slot and utils, each with
`ui8kit.config.json` and `ui8kit.lock.json`. Install or refresh one runtime:

```
cd packages/kit/react
bunx ui8kit@3 init -y --framework react      # once: ui8kit.config.json, src/utils, .cursor/rules
bunx ui8kit@3 add --all                       # 19 primitives + slot from @ui8kit/registry 3.x
bunx ui8kit@3 check                           # offline: missing, modified, mixed versions
bun run kit:check                             # from the root: ui8kit check in every packages/kit/*; part of bun run check / verify
```

Never edit `packages/kit/**` by hand (`ui8kit check` fails).

### Compositions (`packages/kit-compose`) and gates (`packages/ui-gates`)

- `packages/kit-compose`: the former xgen bricks (Stack, Group, Grid, Container, Title, Card*, Badge, List*, Table*, Skeleton, styled
  Button/Link/Input, ...) as **compositions over the v3 primitives** with token-only recipes. One description (`src/map.ts` +
  `variants/*.variants.json`), a thin build (`bun run compose:build`, `compose:check` in `bun run check`), output per runtime like the kit:
  `packages/kit-compose/<runtime>/src/compose`. Map: [docs/ui8kit3-brick-map.md](docs/ui8kit3-brick-map.md).
  These compositions are **candidates for moving into the shared registry** (a compose registry on top of @ui8kit/registry).
- Tests (`bun run test`): DOM parity of every composition between runtimes, the rendered HTML of every case through html-validate and
  axe-core (jsdom), recipes: colors only by tokens, no half steps.
- `packages/ui-gates` (portable, no repo deps): `ui-gates source <dirs>` fails on a raw HTML tag where a primitive exists and on a Box/Text
  `tag` outside the HTML5 allowlist (tsx/jsx, svelte, vue, templ, twig, latte, jinja2); `ui-gates html <cases.json>` runs html-validate +
  axe-core. `bun run gates:source` is part of `bun run check`.
- Migration status: done. Compositions and the 224 organisms on all 8 runtimes (parity with React on the 474 gallery block cases of the
  92 blocks), screens and the 4 host apps on compose-gen; magazine, discovery, panorama and taste-screens import `@codegen-x/svelte-compose`.
  The private xgen copy (`xgen/`, `vendor/codegen`, `packages/<runtime>/ui`) is removed; its last state is the tag `xgen-archive-2026-10-24`.

## Commands

```
bun install
bun run build         # compositions (compose:build), organisms (8 runtimes), server organisms, screens + host apps + packages/shared/app
bun run check         # xgen-exit-guard, kit:check, compose:check (compose-gen check + build --check of every generated tree), gates:source,
                      # skins --check, codex blocks --check, rules gate
bun run typecheck     # svelte-check / tsc / vue-tsc on the compose packages, the shared core, the hosts, magazine, discovery, panorama, taste-*
bun run test          # bun test: kit-compose (DOM parity of 8 runtimes with real engines), ui-gates, skins, rules, compose-gen, taste-data
                      # (templ needs Go, twig/latte PHP + composer, jinja2 Python; each skips without its toolchain, UI8KIT_REQUIRE_ALL_RUNTIMES=1 makes a skip fail)
bun run build:hosts   # vite build of the four host apps (every screen is a lazy chunk)
bun run e2e           # compose-gen e2e: every screen in every built host (plans, site, themes, gallery, catalog, skins), screenshots,
                      # DOM pair test of the 4 hosts, html-validate of every state (needs build:hosts first; COMPOSE_E2E_ONLY=<screen-key>,... to filter)
bun run check:all     # build + check + typecheck + build:hosts + test + lint:px + e2e
bun run verify        # check + codex:validate + typecheck + test
bun run lint:px       # ui8px over the class sets of the specs (8 px grid, 4 px steps only in controls), hard gate: 0 blocking hits (.ui8px/gate.json)
bun run audit:push    # before every push: nothing private, no images/fonts/.fig, no secrets
bun run rules          # rules 01/02/03/06 on the composition zone (also part of bun run check)
bun run rules:baseline # rewrite rules/zones.json and rules/baselines after an accepted change
bun packages/compose-gen/check.ts [--write]   # compose-gen check alone; --write rewrites the authored JSON specs and the coverage doc
```

`compose-gen check` groups: authored, schema, registry, themes, routes, dictionary, text, dead, duplicates, readability, structure, versions.
The kit-compose tests replace the old real-engine parity groups (templ, solid, twig, jinja2, latte); the rules gate (`packages/tooling/rules`)
holds the rules and the style groups (corners, shadows, hardcode, spacing).

## What is in the kit

| | |
|---|---|
| primitives | 19 UI8Kit 3 primitives + slot per runtime (`packages/kit/<rt>`) |
| compositions | the former bricks (Stack, Group, Grid, Container, Title, Card*, Badge, List*, Table*, ...) as compositions over the primitives (`packages/kit-compose/src/map.ts` + `variants/`) |
| parts / patterns / organisms | **23 / 36 / 184** specs (`packages/compose-gen/specs/{parts,patterns,organisms}`), 224 organisms generated per runtime |
| blocks | **92** blocks, **474** variants (`packages/compose-gen/specs/blocks`) |
| screens | **15** screen specs: plans, site, blocks gallery, catalog, skins and ten themes |
| data | Codex collections in `packages/compose-gen/fixtures`, texts in `packages/compose-gen/content/ui/en.json` |
| runtimes | Svelte 5, React 19, Vue 3, Solid (packages + host apps); Go templ, Twig, Jinja2, Latte (template packages) |

Text is never written in a view: a text is a reference into the content dictionary (or into the `labels` an organism receives).
Cyrillic is not allowed in any tracked file: sources, generated code, content, docs, plans and reports (`compose-gen check`, group `text`,
which scans `git ls-files`). Genuine locale files would go in `CYRILLIC_ALLOW` in `packages/compose-gen/check/src/groups/text.ts`; the list is empty.

## compose-gen

| folder | job |
|---|---|
| `packages/compose-gen/schema` | JSON Schemas (spec, variants, organism, screen, app, collection, dictionary), validator, spec versions, codex manifest/validate/blocks |
| `packages/compose-gen/spec` | the typed render model, expressions, naming, tags and recipes (cva with compound variants) the emitters share |
| `packages/compose-gen/screens` | the view IR, the builder of organisms and screens (`src/authoring`), view validation, loaders, `tools/author-*-texts.ts` |
| `packages/compose-gen/runtimes/core` | what the emitters share: types, expression printer, view walker, runtime assets (app runtime, styles, ts) |
| `packages/compose-gen/runtimes/<rt>` | the emitters: svelte, react, vue, solid (organisms, screens, host scaffold), templ, twig, jinja2, latte |
| `packages/compose-gen/check` | `compose-gen check` groups (`src/groups`) and the host e2e (`src/e2e`) |
| `packages/compose-gen/parts.ts` | the parts table read from the kit-compose map (the bridge from compositions to the specs) |

The build scripts live in `packages/kit-compose/src`: `build.ts` (compositions), `organisms.ts` (JS organisms), `server-organisms.ts`
(templ, twig, jinja2, latte), `hosts.ts` (screens, host apps, `packages/shared/app`). Each takes `--check`. History: `docs/ui8kit3-xgen-exit.md`;
`packages/compose-gen/specs/_nonportable.json` lists what does not carry over between the runtimes and the contract that replaces it.

## Generated packages

`@codegen-x/svelte-compose`, `@codegen-x/react-compose`, `@codegen-x/vue-compose` and `@codegen-x/solid-compose`
(`packages/kit-compose/<rt>`): source only, no build step, the consumer's Vite compiles them. The template packages
(`packages/kit-compose/{templ,twig,jinja2,latte}`) hold the same compositions and blocks as server templates with their helpers.
Tokens and classes come from the theme. Text only through props.

One corner token: every corner is plain `rounded`, which reads `--radius` (0.625rem = 10 px, set in `@theme` in
`theme.css`); change that one value and every corner of the kit follows. `rounded-full` is kept only where the shape is
the meaning (the radio control, the switch track and knob, avatars, timeline status dots, badges and status pills), `rounded-none` only for
functional resets (the full-screen dialog sheet, edge-to-edge backdrop pictures). The `corners` group of the rules gate
fails on any other `rounded-*` class and holds the exceptions in an allowlist with a reason each
(`CORNER_ALLOW` in `packages/tooling/rules/src/audit-rules.ts`). There are no decoration-only options (no corner `shape` props, no
raised cards, no accent tone, no dotted textures or position dots); the full list of what ui8kit 2.0 removed is in
`plan/UI8KIT-2.0.md`, section 7.6.

Shadows: flat surfaces (cards, panels, sections, buttons, inputs, tiles, nav and switcher items) have none. Only floating
layers have one shadcn shadow: dialogs and sheets `shadow-lg`, menus and popovers `shadow-md`, a toast fixed to the
corner `shadow-lg`. The `shadows` group of the rules gate fails on any other shadow class and holds the floating specs in
`SHADOW_ALLOW` with a reason each; `kit.css` draws no shadow (only focus rings).

Controls share one scale: `sm / default / lg` = `h-8 / h-10 / h-12` (Button, Input, Select, Switcher; Textarea by
min-height), Badge `h-5 / h-6 / h-8`, Avatar `xs`-`xl` = 24-64 px, icons 16 / 20 / 24 (12 only inside dense controls),
text-xs as the smallest type. As in shadcn, the Button size sets the text (`text-sm`, lg `text-base`) and buttons and
badges are `font-medium`; Input and Textarea are `text-base md:text-sm` (16 px on phones), Select `text-sm`. Text and
Title sizes use the Tailwind type-scale names (`xs sm base lg xl 2xl 3xl 4xl 5xl`). A Card pads once (`p-6`, compact
`p-4`); CardHeader, CardContent and CardFooter add no padding of their own (note: the kit-compose map currently gives them
`p-6` / `p-6 pt-0`, a difference from UI8Kit 2 seen in the visual check, to be reconciled). `Stack` / `Group` `Gap` keys are Tailwind steps
(`0 2 4 6 8 10 12 auto`, `Gap "4"` = `gap-4`); the `spacing` check rejects pixel-named spacing keys. Section 8 of `plan/UI8KIT-2.0.md` lists
the polish rounds and their breaking changes.

The same four groups (`corners`, `shadows`, `hardcode`, `spacing`) also read the hand-written code of `apps/magazine/src`
(`packages/tooling/rules/src/style-zones.ts`): only style text, meaning `class` values and `<style>` of `.svelte` files, `.css` files
and the class strings of `.ts` files. Three.js and canvas engine code (`packages/panorama`) is outside every rule zone. They report a `rounded-*` class or a `border-radius` off `var(--radius)`, a shadow class or drop
`box-shadow`, gradients, arbitrary values, palette and hex colors, and spacing off the 8 px grid (odd steps, px not a
multiple of 8; 4 px belongs inside controls). Existing findings are recorded per file in
`rules/style-baselines/<package>.json`; a new one fails, a fixed one asks for `bun run rules:baseline`.

```ts
import { Button, Card, PricingCard } from "@codegen-x/svelte-compose";   // or react-, vue-, solid-compose
```

```css
@import "@codegen-x/svelte-compose/styles/index.css";   /* Tailwind v4 */
```

## Blocks

A block is an organism plus its axes (layout, columns, media side, density, tone, emphasis, ...), named variants and the data it reads: JSON, no markup (`packages/compose-gen/specs/blocks`). The catalog has 92 blocks and 474 variants in 8 topics (marketing, commerce, promo, content, account, dashboard, onboarding, support).
A page can be a **composed** screen (a list of blocks with variants); the gallery screen (`blocks`) is built from the catalog. Details: [docs/xgen-legacy/blocks.md](docs/xgen-legacy/blocks.md) (written for xgen, the model is unchanged).
Coverage of the reference catalog: [packages/compose-gen/docs/vibeui-coverage.md](packages/compose-gen/docs/vibeui-coverage.md) (written by `compose-gen check --write`).

## What is in git

Only code, specs, schemas, fixtures, content and docs. Never: `private/`, `shots/`, `.fig`, `public/p/`, images, fonts, secrets.
`bun run audit:push` checks the diff against `origin/main` before each push. License: MIT ([LICENSE](LICENSE)).

## Host apps (screens as data)

| | Svelte | React | Vue | Solid |
|---|---|---|---|---|
| app | `apps/host-svelte` | `apps/host-react` | `apps/host-vue` | `apps/host-solid` |
| dev / preview port | 5180 | 5181 | 5182 | 5183 |
| a screen | `http://127.0.0.1:5180/<screen>/#/<route>` | `http://127.0.0.1:5181/<screen>/#/<route>` | `http://127.0.0.1:5182/<screen>/#/<route>` | `http://127.0.0.1:5183/<screen>/#/<route>` |

`<screen>` is the screen id without `screen.`: `blocks`, `catalog`, `skins`, `plans`, `site`, `theme-<name>` (ten themes). `/` lists every screen; `?screen=<key>` works too.
Each host loads one screen per chunk; the generated part of a host is `gen/` (App, runtime, screens). Dictionary, data, menus and runtime core
live once in `packages/shared/app` (`@ui8kit/app-shared`).
