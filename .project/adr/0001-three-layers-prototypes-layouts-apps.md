# ADR-0001: Three layers: prototypes, layouts, apps

Status: Accepted
Date: 2026-10-27
Slug: three-layers-prototypes-layouts-apps
Deciders: owner (Smarty Cab)
Related: ui8kit/contract `.cursor/rules` (00 to 05), plan/CODEGEN-X.md §1 (export a preset, `npx cgenx`), plan/MAGAZINE.md

## Context

- The repository has two hand-written storefront apps on the same kit: `apps/magazine` (the taste journal) and `apps/stock`
  (a stock-site storefront, S0: header with the search, empty results). Both import `@codegen-x/svelte-compose`.
- The prototype layer (blocks and organisms) is generated by compose-gen onto `packages/kit-compose/<runtime>` and checked
  strictly: the rules gate detectors, `ui-gates source`, DOM parity on 8 runtimes, html-validate + axe-core, and 8+4 spacing
  through `lint:px` (ui8px gate, `max: 0`, scope: the class sets of `packages/compose-gen/specs`).
- The app structure is not a layer of its own. Magazine keeps its structural parts in `apps/magazine/src/parts`, `src/feed`,
  `src/theme` next to routes, data and brand CSS (`src/magazine.css`, `mg-*` classes injected as `<style data-snapshot-skip>`).
  At commit `6919108e` its rules baseline records 230 `raw-native-tag`, 11 `reactive-aria`, 6 `literal-text`
  (`rules/baselines/magazine.json`) and its style baseline 6 corners, 2 shadows, 22 spacing, all in `src/magazine.css`
  (`rules/style-baselines/magazine.json`). `src/theme` is not in any zone. Stock records zero everywhere.
- The style groups (corners, shadows, hardcode, spacing) scan only `STYLE_PACKAGES` = `apps/magazine`, `apps/stock`
  (`packages/tooling/rules/src/style-zones.ts`); the spacing group there applies 8+4 to app code, which contradicts the
  contract rule "screens and applications are brand taste: 8+4 does not apply to them".
- The end goal of the product: give the visitor ready code of a screen with every dependency it needs: the primitives, the
  organisms and the styles (tokens, skin).

## Decision

1. **Prototypes** (blocks, organisms; `packages/compose-gen` specs, generated `packages/kit-compose/<runtime>`): every UI8Kit rule,
   including 8+4 spacing through ui8px. Unchanged.
2. **Layouts**: a new package, proposed name `packages/layouts`, holds the structure of the apps:
   - Stock: header, type bar, quick filters, facet column, chips row, card grid, preview frame, pagination, asset card.
   - Magazine: the structural parts now in `apps/magazine/src/parts` and `src/feed` (card, search, the design system panels,
     collections, rows, the feed sections, the filter groups, ...).
   Layouts are checked as strictly as prototypes: the structural detectors (`block-root`, `raw-html`, `dynamic-tag`,
   `raw-native-tag`, `reactive-aria`, `literal-text`), 8+4, colors only through tokens, zero baseline. Texts come in through props;
   data comes from the search engine, which also moves into a package (Magazine already reads `@ui8kit/taste-data/search`).
   Apps consume layouts from the package.
3. **Apps** (`apps/stock`, `apps/magazine`): only assemble layout + data + routes + brand theme. Screens are free in brand style:
   no 8+4 and no spacing group for apps.
4. **The retag rule always applies, screens and apps included**: no bare HTML tags (`header`, `a`, `span`, `div`, `button`, `img`,
   `svg`, `input`, `ul`/`li`, ...); only the framework's UI8Kit primitives with the `tag` retag (`Block tag="header"`, `Text tag`,
   `Title as`), by the UI8Kit contracts.
5. Taste screens (`packages/taste-screens`) stay with Magazine (the taste journal); they are app-level brand screens, under rule 4.
6. End goal: a visitor can take a screen's code with every dependency (primitives, organisms, layouts, styles and tokens) as one
   self-contained set.

## Consequences

- Zones and style rules:
  - `packages/layouts/package.json` gets a `ui8kit` field (composition and blockRoot over its sources), so `rules/zones.json`
    gains it with an all-zero `rules/baselines/layouts.json`.
  - `STYLE_PACKAGES` gets `packages/layouts` with all four groups; the apps keep `corners`, `shadows`, `hardcode` but drop
    `spacing` (the style groups become per-package; today they are one list for all four groups).
  - 8+4 for layouts needs a scan that reads `.svelte`: the ui8px gate reads only the specs extract
    (`packages/tooling/bin/ui8px-extract.mjs`); either a layouts extract for ui8px or the rules gate spacing group on layouts.
  - `raw-native-tag` must cover the whole of each app (`apps/magazine/src/theme` is outside every zone today; the zone lists are
    per directory and opt-in). Target: every `.svelte` under an app's `src` is composition, except an explicit kit list.
- Migration of Magazine parts: the structural parts move to `packages/layouts` with props for texts and data, retagged to
  primitives, their `mg-*` classes replaced by token utilities of the kit; what stays in the app is data, routes, the theme state
  and brand CSS. The 230 recorded raw tags are cleared on the way (in the package from the start; in the app before the move or
  together with it). The snapshot cache depends on the document CSS (`apps/magazine/src/app.css`), so the move must keep the
  stylesheet that snapshots carry equal to Discovery's, or accept one re-rasterisation.
- Stock builds its next steps (type bar, filters, facets, chips, grid, preview, pagination) directly in `packages/layouts`.
- Export goal: a screen's dependency closure (screen -> layouts -> organisms -> compositions -> primitives, plus styles,
  tokens, skin) has to be computable and emitted as one set. No such emitter exists today (see Open risks).
- The contract rules (`ui8kit/contract` `.cursor/rules`, `AGENTS.md`, skills) state the three layers, retag everywhere,
  and 8+4 for prototypes and layouts only.

## Alternatives considered

- Keep the structure inside each app and check the apps strictly (8+4 included): rejected; it puts brand taste under the
  prototype grid and keeps the structure unshareable between Stock and Magazine and unexportable.
- Put the app structure into compose-gen specs (generated organisms on 8 runtimes): rejected for now; layouts are Svelte
  app structure with app state (search, URL, snapshots), not yet portable specs. They may become specs later.
- Two layers only (prototypes and apps) with screens free of the retag rule: rejected by the owner; every screen must stay on
  the framework primitives so its code is clean and exportable.

## Open risks

- The export of a screen with its dependencies has no tool yet: the hosts import the `@codegen-x/<runtime>-compose` barrel
  (whole package), styles come from `packages/kit-compose/<runtime>/src/styles` plus `packages/skins` / `@ui8kit/app-shared`
  styles; nothing computes a per-screen closure. Not checked: how `npx cgenx` (plan/CODEGEN-X.md) will pull it.
- Magazine's snapshot cache keys hash the document CSS; moving markup to token utilities may change them.
- 8+4 on `.svelte` layouts: the tool path (ui8px extract or the spacing group) is not decided.
- The package name `packages/layouts` is a proposal.
